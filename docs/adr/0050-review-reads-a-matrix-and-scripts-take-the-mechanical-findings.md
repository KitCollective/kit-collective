# A review reads a matrix, scripts take the mechanical findings, text fixes are checked light, and waiting for checks is one command

Nicklas, 2026-10-10, after `/issue-session` landed KIT-267, 271, 272, 277, 279 and 280. Review found something new every round: KIT-277 failed three times in one state machine, KIT-267 five times, KIT-272 four times, the last on a naming rule that existed from round 1. Sessions also stopped to ask the human whether CI was green, because the cursor-ratchet hook forbids polling. Device flows were settled separately in ADR-0049. This one changes the review loop. Four decisions:

1. **The review writes a matrix; the next review inherits it.** Under workpad `### Review matrix` there is one row per lock-set row (`scripts/lib/review-matrix.mjs` `LOCK_ROWS`): the six rows of the checker's lock set, plus `device-flow`, `state-machine`, `names-english` and `docs-sync`, the classes the three evidence issues failed on. A row is `checked`, `N/A` or `finding`, with evidence and the SHA it was read at. A review may not give a verdict while a row is empty (`node scripts/review-matrix.mjs validate`). The next review does not start from a blank page: `node scripts/review-matrix.mjs plan <workpad> <lastReviewSha>` lists the rows to re-check (every row still a finding, the state rows `spec-ac`, `mergeable` and `required-checks`, and any row whose paths the new diff touches) and the rows it inherits as they stand. This changes "every pass is a complete review of the current diff" in `WORKFLOW.md`: the first pass still reads everything, later passes read what changed, and a regression the fix created falls under a touched row. `state-machine` is the row that would have ended KIT-277 in one round: when the diff touches a reducer or machine, every state, transition and guard of it is walked in one pass, not the one the last finding named.
2. **Mechanical checks are scripts, in CI and in the pre-review gate.** A reviewer's judgement is spent on what a script cannot see. Two scripts exist now, both run by `pnpm check:review-gate` before `In Review` and by the CI `test` job: `scripts/check-code-english.mjs` (a declared name or code file name that is Danish, using the commit hook's scanner, whose stems now include `komigang`, `tilfoej`, `fortsaet`, `trøje` and which flags any `æ`, `ø` or `å` in a declared name; shipped Expo route slugs are exempt) and `scripts/check-doc-references.mjs` (a living doc that still names a symbol, prop or Device-flow step the diff removed, or names a repository path that does not exist on a line the diff added). ADRs, `.scratch` specs and archived notes record history and are not read. KIT-272 review 4 (`KomIGangFace`), reviews 2 and 3 (flow steps and a removed prop named in docs) and KIT-267 review 5 (a script under the wrong directory) are the tests. A finding that a script could have made is now a gate failure, not a review round.
3. **A finding that is only text or a name gets a light check, and does not count toward the loop cap.** Review tags such a finding `[text]` (a doc, a comment, a copy line) or `[name]` (an identifier or file name). When **every** finding of a fail is tagged, the session fixes in place and runs `node scripts/classify-fix-diff.mjs <lastReviewSha>`: `light` means the fix diff is docs and comments, or one consistent rename with no test losing a line, and then the verification is the reviewer reading that diff against each finding plus the gate scripts, not a new fresh full review. `full` means the tag was wrong or the fix changed behaviour: the normal loop applies. A light fail increments `lightFixes`, not `reviewLoops`; three light fixes on one issue count as one `reviewLoops` so the cap still ends a loop that never converges. The classifier is the guard against calling a behaviour change a rename.
4. **Waiting for required checks is one blocking command.** `node scripts/wait-for-checks.mjs <pr>` polls inside the process, prints a line per change and exits `0` green and MERGEABLE, `1` red, `2` still pending at the timeout (default 30 minutes), `3` green but not mergeable, `4` unknown. The cursor-ratchet hook still denies the watch flag of the checks command, sleep loops and `for`/`while` over it: the hook sees one command, not a poll, so nothing is loosened; its denial message now names this script. A Desktop session runs it in the background (the harness re-invokes the session when it exits) or in the foreground when nothing else is left to do. A session never asks the human whether CI is green; it asks only on exit `2` or `4` twice in a row. Device flows are the exception to "required": `device-run.sh` sets that status itself, and `--also "Device flows"` makes the wait include it.

What this gives up: a text finding is no longer re-judged by a fresh reviewer with an empty conversation, only by a read of the fix diff; the classifier narrows that to diffs that cannot change behaviour. The matrix trusts the previous review's `checked` rows unless the diff touches them, so a row's path globs have to be kept honest: adding a lock-set row means adding its globs and a test.

Tried while deciding: a 5-axis review instead of a matrix (more parallel sub-agents, same blank page every round); tagging findings only, with no classifier (a `[name]` finding that hides a logic change would skip review). Not tried: the matrix as a Linear custom field rather than workpad text.

Status: accepted. Changes `WORKFLOW.md` "Checker run" (every pass is a complete review) for passes after the first, and `docs/agents/error-ratcheting.md` (the CI-sleep hook).
